# Relay3 应用异常诊断（v0.3.6）

使用 [electron-log 5.4.4](https://github.com/megahertz/electron-log) 写入本地文件，配合 Electron crashReporter 收集本地崩溃转储；不自动上传。

## 覆盖范围

- 主进程：未捕获异常、未处理 Promise 拒绝、Node 警告、启动和关闭失败。
- 页面：全局 JS 错误、未处理 Promise 拒绝、React 渲染错误、资源加载失败、错误级控制台信息、预加载失败、页面失去响应和页面进程崩溃。
- 业务：统一 HTTP/API 与 IPC 失败、群聊操作错误、WebSocket 异常、文件上传及读取错误、缓存清理错误。记录操作路由和状态，不记录请求正文或凭证。缓存目录迁移记录复制前后、设置落盘与原目录清理阶段，便于定位本次 Windows 闪退。
- 手机网页：已连接后的异常通过经过身份校验的诊断接口记录到中转站。未连接、网页关闭或网络不可达时无法保证送达；不提供公网遥测。
- 非正常退出：启动时检查上次运行标记。正常退出删除标记；硬杀进程、断电或原生崩溃后，下次启动提示日志中有非正常退出记录。

全局采集无法覆盖每一种故障：硬杀、断电、磁盘无法写入、网络断开等可能来不及记录错误堆栈；原生转储补充崩溃信息，不保证一定生成。已有业务代码仍须在主动吞掉的错误处接入诊断；后续新增功能应使用统一 request、IPC 包装及 diagnostic/reportException。

## 查看、导出和清理

桌面设置页展开“诊断日志”，可以复制日志路径、打开目录、导出 ZIP 或确认后清理。崩溃后重新启动应用再导出，尽量在复现后立即导出，避免旧日志轮转。

- Windows：`%APPDATA%\relay3\logs`；原生崩溃数据在 `%APPDATA%\relay3\crash-dumps`。
- macOS：`~/Library/Application Support/relay3/logs`；原生崩溃数据在同级 `crash-dumps`。
- 路径沿用原应用数据目录，不随缓存路径改变。日志采集不依赖 SQLite，可在数据库或缓存操作失败时记录。

ZIP 含日志、版本、Electron/Node 版本、系统平台和架构、导出时间以及已有崩溃转储；不导出数据库、聊天密钥、文件缓存或接收文件。导出原始文件最多 50 MB，超出的条目列在 manifest 的 skipped 中。

普通日志保留约 30 MB（当前文件与 5 个轮转文件，每个约 5 MB）。崩溃转储在启动时整理，最多保留最近 20 个且总量约 100 MB。页面上报每分钟限 20 条，避免循环错误快速占满磁盘。

凭证、配对链接参数和长十六进制密钥自动脱敏，不主动采集聊天正文和文件内容。日志包含故障相关路径与系统信息；**原生崩溃转储可能包含进程内存中的敏感信息，分享前应确认接收人可信**。

## 排查 Windows 缓存路径闪退

1. 安装 v0.3.6，关闭中转站，再选择独立的空缓存目录保存。
2. 若闪退，重新打开应用，在“设置 → 诊断日志”导出 ZIP。
3. 一起提供复现时间、原目录和新目录所在磁盘类型（本地磁盘、移动硬盘或网络盘）。拿到日志后再判断原因。

本版增加采集能力，未宣称已修复尚未取得日志的 Windows 闪退。
