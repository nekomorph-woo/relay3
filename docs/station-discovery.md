# 桌面中转站自动发现

Windows 和 Mac 的 Electron 客户端打开「连接中转站」，自动发现同一局域网中已开启的 Relay3 中转站。点击中转站名称自动填入地址，再输入六位一次性配对码；已经配对的中转站可直接重连。手机浏览器继续扫码，不增加发现功能。

## 使用与兼容

- 中转站和桌面客户端都需要包含此功能的新版本。v0.3.7 及更早的中转站不会广播，仍可手动输入地址或使用历史连接。
- 列表展示名称、PC/Mac 标记、地址与在线设备数。广播收到后验证 `/api/info`，不可达的中转站禁用选择并提示检查防火墙和代理。
- 选择中转站后收起重复的地址表单和历史列表；可通过「手动输入地址或配对链接」恢复。
- 名称、端口变更更新广播；关闭中转站停止广播；退出连接弹窗停止客户端发现，但本机仍开启的中转站继续广播。
- 相同 stationId 合并，多网卡地址逐个验证。地址变化后按 stationId 复用原有配对凭证；新中转站仍需配对码。

## 协议与边界

使用纯 JavaScript 的 bonjour-service 1.4.4，通过 mDNS/DNS-SD 发布 `_relay3._tcp.local`。不依赖 Windows 安装 Bonjour，不扫描网段，不连接云端。

TXT 仅包含协议版本、应用标识、中转站 ID、名称和平台；不广播配对码、连接凭证、聊天密钥或历史记录。发现不是授权，也不能验证服务器的密码学身份。提交连接前再次核对中转站 ID，实际加入仍由已有配对认证处理。

验证仅请求候选 IPv4 局域网/回环地址的固定 `/api/info`，不附凭证、不跟随重定向；每次请求最多 1.8 秒、16 KiB，最多 4 个并行任务、32 条广播服务记录、每服务 8 个地址。弹窗打开期间每 10 秒重新发现与验证，35 秒未收到广播的条目移除，正常关闭的退出广播可立即移除。

Electron 探测使用与页面相同的 Chromium 直连网络配置。Proxifier、TUN、VPN 等系统级网络拦截仍可能影响访问，需将局域网设为直连。防火墙需允许 Relay3 的 UDP 5353 发现以及中转站 TCP 端口；客户端不会自动修改防火墙。跨子网、访客 Wi-Fi 或设备隔离可能阻止发现，保留手动连接兜底。

Mac 打包配置包含局域网用途说明和 `_relay3._tcp` Bonjour 服务声明；若系统要求局域网访问权限，需要允许 Relay3。

## 验证（2026-10-05）

- 类型检查、前后端构建通过。
- 25 项服务测试通过，包括发现的地址过滤、身份不匹配、多网卡、去重、取消、生命周期、并发/数量限制、UDP 错误和 HTTP 响应限制。
- Mac Electron 与独立中转站进程使用真实 mDNS 完成自动发现、首次数字配对、地址变更后复用凭证、更名/关闭更新、本机中转站自动广播。
- 原有桌面/手机传输与重连的 10 项 UI 回归通过。
- 自动化工具的 Node 调试 WebSocket 受本机代理影响，使用测试专用 Unix socket 桥接回环连接；没有改动用户代理设置，也没有把桥接代码加入产品。

- Windows 实机双端发现、Windows 防火墙及 Mac 安装后的系统局域网权限提示尚需实机验证；未发布安装包、未打 tag。
