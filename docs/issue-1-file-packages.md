# 文件包实现与验收

对应 Issue 1：https://github.com/nekomorph-woo/relay3/issues/1

## 使用方式

- 普通传输和群聊的每次发送统一形成一个文件包，单文件同样适用；每包最多100个文件，不生成ZIP。
- 全部成功上传后成包，成功成员先暂存。失败时在包内重传原文件，或移除未成功成员再成包。成包后文件和接收名单不可修改，可取消整包。
- 接收者默认展开文件列表，可以接收单项，或跨页选择多个文件批量下载；文件8项一页，设备4项一页并支持搜索。
- 发送者按文件查看总体接收数量，也可按设备展开逐文件状态、最近下载时间和传输耗时。手动提醒在线未处理者，提醒不会切换页面，点击后打开对应站的包详情。
- 群聊以FileBox入口呈现，一个包只生成一条消息；点开进入文件包弹窗。未授权设备只能看到通用入口、发送者、时间和公开备注。
- 中转缓存按包分组，可展开文件、定位文件、选择整个包清理；清理有确认弹窗，传输中的缓存会跳过并报告。
- 旧记录保留原有展示，不回填为包。对未声明文件包能力的旧中转站沿用逐文件投递。

## 数据和状态

新增 `file_packages`、`package_files`、`package_reminders` 和本机 `remote_packages` 表；已有文件、传输及接收文件记录追加可选packageId。

创建清单和发布使用SQLite事务。成包基准取保留成员最后一次上传成功时间，各文件与接收任务写入相同D/T；不从包字段替代各文件期限。D=基准+接收缓冲时间，T=D+创建时的缓存保留设置。再次发布、重新下载或修改站点保留设置不延长期限。

首次下载真正开始前检查D，排队期间过D则跳过；已开始下载可完成。已下载者可在T前重新下载。重启保留暂存成功成员，上传中的成员恢复为失败；24小时未成包自动取消。缓存清理、取消和流收尾不会复活已取消任务，也不会删除本机收到的文件和历史。

群聊每个文件名在发送端加密，绑定中转站、发送者、备注、文件及包标识。只向接收者返回自己的加密包装和接收任务。未知身份不返回文件数量、大小、名单和密文。文件内容沿用普通传输，不加密。

桌面批量下载并发2，浏览器并发1；手机仍需在浏览器完成后确认收到，浏览器可能要求允许多个文件下载。跨站缓存使用站点+包ID区分，快照和传输更新时间阻止较旧响应覆盖最新历史。

## 界面命名优化

- 文件包继续作为内部模型；传输、记录和缓存标题使用单文件名，或“首个文件名 等 N 个文件”。
- 群聊入口在本地解密首个文件名后展示相同标题；未授权终端仍只显示“未知文件”，不请求明细。
- 操作简化为“查看文件”“取消发送”“清理缓存”，详情区域保持“文件明细”“接收设备”；等待上传阶段以“尚未发送”提示。
