# Relay3

当前源码版本：0.3.5（等待确认发布）。最新已发布安装包：[GitHub Release](https://github.com/nekomorph-woo/relay3/releases/tag/v0.3.4)，提供 Mac Apple Silicon 与 Windows x64。

PC、Mac、手机之间的局域网文件互传与文字群聊工具。桌面版支持 Windows 10 及更新版本、macOS 13 及更新版本。桌面端使用 Electron，手机通过浏览器连接，不需要安装客户端。所有前端资源随应用附带，运行时不依赖外网。

## 使用

1. 打开桌面应用，在「中转站」页开启中转站。
2. 本机点击「本机加入」；另一台桌面应用可粘贴配对链接连接。手机扫描二维码，在浏览器里输入设备名称后连接。
3. 在「文件传输」选择在线接收设备与文件，发送请求。接收方确认后，文件上传至中转站，再由接收方下载。
4. 桌面接收会校验大小与 SHA-256，完成后自动保存到接收目录；手机下载后需点击「确认收到」。浏览器不能可靠确认文件最终已保存至系统磁盘。
5. 在「文件存储」查看中转缓存与本机接收文件；展开「存储位置与数据库整理」可查看路径、打开目录或整理数据库。

文件传输页的连接与管理入口集中在页头，当前传输占据主区域。桌面设备、收发记录和存储列表各自滚动；手机按屏幕宽度上下排列。界面与安装包名称统一为 Relay3，升级沿用原有 `relay3` 数据目录。

同一台 PC / Mac 可以同时开启本机中转站，并连接自己或另一台中转站作为客户端。手机只有客户端功能。关闭本机中转站不影响连接另一台中转站的客户端角色。

默认端口为 **42830**，可在关闭中转站后修改。设备需要处于可互访的局域网；首次启动需允许系统防火墙接受连接。访客 Wi-Fi 的隔离设置可能阻止设备互访。配对链接包含连接凭证，请通过二维码或可信渠道交给需要连接的设备。传输使用局域网 HTTP，适用于可信的家庭或办公局域网。

## 存储与清理

| 数据         | Windows                      | macOS                                   |
| ------------ | ---------------------------- | --------------------------------------- |
| 应用数据     | `%APPDATA%\relay3\`          | `~/Library/Application Support/relay3/` |
| 数据库       | 数据目录内的 `relay3.sqlite` | 同左                                    |
| 中转缓存     | 数据目录内的 `relay-cache/`  | 同左                                    |
| 本机接收文件 | 系统下载目录内的 `relay3/`   | 同左                                    |

- 数据库保存设备、连接时间线、传输历史、群聊历史、阅读游标、公钥、设置及本机接收文件信息；使用 WAL 日志保证持久性。
- 收发历史不会自动清理。桌面端保存自身经远端中转站的收发历史；本机中转站保存所有经它处理的历史。
- 中转缓存以唯一 ID 命名，`partial/` 存未完成上传，`ready/` 存完整文件。
- 仅「已完成」文件默认在确认接收后 **1 小时**自动清理。每 30 秒检查一次；应用关闭期间不会运行清理，重启后处理已到期缓存。待接收、失败或取消的文件需手动清理。
- 可修改保留时间，修改后的规则也应用于现有已完成缓存。
- 中转缓存位置可迁移到空目录；需先关闭中转站。迁移复制成功后再更新设置并移除旧目录。
- 本机正式接收文件不会自动清理；可以在应用里单独选择并永久删除。缓存清理不会删除正式文件。
- 「收发记录」支持手动清理已结束且本机缓存已删除的历史；「连接设备」支持清理没有待传输文件的离线设备历史。设备历史清理后需重新配对。
- 「整理空间」执行 SQLite checkpoint 和 VACUUM，仅回收空间，不删除记录。不要直接删除正在使用的 SQLite 或 WAL 文件。

## 开发与验证

需要 Node.js 24 或更新版本。

```sh
npm ci
npm run dev
```

```sh
npm run build
npm test
npx playwright install chromium
npm run test:ui
```

服务端测试覆盖配对权限、接收确认、流式上传、大文件完整性、拒绝和取消、手动与定时清理、缓存迁移、数据库整理和重启恢复。桌面集成测试直接启动 Electron，验证手机页面双向传输、正式文件落盘、清理后的历史、响应式布局、设备断开以及同时运行中转站与远端客户端。

macOS 服务测试使用系统 curl 直连回环地址，绕开系统代理对 Node HTTP 客户端的干扰。Playwright 还需要 Node 能直连本机调试 WebSocket；如果代理按进程接管 Node，请把它的 localhost 访问设为直连后运行集成测试。

只启动网页中转服务（仍使用同一份数据库实现）：

```sh
npm run serve
```

控制服务仅监听 `127.0.0.1` 的随机端口，中转站开启后才监听局域网。管理接口需要独立凭证，不向手机客户端开放。Electron 使用沙盒、上下文隔离、受限 IPC 与 CSP，禁用 Node 集成和额外窗口导航。

## 打包

```sh
npm run dist:mac       # macOS Apple Silicon DMG
npm run dist:mac:x64   # macOS Intel DMG
npm run dist:win       # Windows x64 安装程序，建议在 Windows 构建
npm run pack          # 本机未压缩应用目录
```

产物位于 `release/`。GitHub Actions 提供 macOS / Windows 原生构建与检查，可在确认发布后构建并上传 Release。Windows 安装包使用支持 Apple Silicon 的 NSIS 3.12 工具集，跨平台打包不要求安装 Rosetta。

安装包只包含编译产物和运行依赖，分别打包 CPU 架构，使用 ASAR 与最大压缩，保留中文和英文语言资源。不附带额外 Node 运行时、外部字体、开发依赖或 source map。SQLite 使用 Electron 的 Node 内置模块，无需打包原生 SQLite 插件。

应用、Dock、安装程序均使用 Relay3 专属图标。品牌原稿位于 `design/branding/`。

当前为未配置商业签名和公证的本地首版；正式分发可在构建环境配置 Apple / Windows 签名凭证。iOS / Android 实机后台与下载行为需依据系统浏览器验证，浏览器离开前台后可能暂停传输。

## 数字配对与设备管理

中转站二维码旁显示 6 位一次性配对码，有效期为 5 分钟，成功连接后立即作废并生成新码。客户端填写中转站局域网地址与数字配对码即可连接，不必传递完整配对链接。数字配对码不是服务器地址，仍要求终端处于互通的局域网；手机先在浏览器打开中转站页面。扫码及原连接凭证仍可使用。

所有终端在设置中均可更换设备身份。更换会断开连接、取消未完成传输并忘记本终端保存的配对凭证，新的身份需要重新配对。中转站记录与已保存文件不会因更换身份而删除。浏览器身份按站点保存在本地存储中。

中转站设备列表支持逐台清除，无论在线或离线；在线设备会被断开，旧凭证撤销，未完成传输取消。批量清理离线历史可按最近一次连接时间选择 1 小时、24 小时、7 天或 30 天之前；在线设备保留。清理设备不会删除收发记录或文件。

桌面复制使用系统剪贴板。网页自动复制被拒绝时，尝试兼容复制；仍不可用时显示可手动选中的内容。

## 群聊大厅（v0.3.4）

连接中转站后，在「群聊大厅」发送文字。消息显示发送者、时间、原文和复制按钮，不渲染 Markdown 或 HTML，也不支持图片、文件、编辑或撤回。正文最多 10000 个 Unicode 字符。桌面采用消息流、底部输入区和右侧设备信息栏；窄屏用「大厅信息」抽屉查看中转站与在线/离线设备，设备列表每 30 秒刷新。

普通消息默认明文发送。点击「发送密文」打开独立弹窗，填写正文、选择接收设备与公开备注。可以选择在线设备，以及曾连接并登记公钥的离线设备，发送者固定包含；按在线状态和本机最近选用顺序排序。普通与密文草稿独立，关闭弹窗不会把密文草稿放进普通输入区。

每台设备生成 X25519 公私钥，使用 HKDF-SHA256 和 AES-256-GCM 在发送前加密正文，分别为接收设备封装消息密钥。中转站保存密文封包，接收设备本地解密。可解密消息标记开锁图标；其他设备显示锁图标和 100 条内置趣味句子中的随机一条，复制时复制真实密文。公开备注最多 1000 字符，提供提示、说明、线索三种样式，所有设备可见并可单独复制；备注不提供解密权限。此方案不包含独立验证公钥的流程，仍以可信局域网和可信中转站为使用前提。

桌面私钥保存在应用数据目录的 `chat-keys/<设备ID>.json`；手机私钥保存在该中转站地址对应的浏览器本地存储。请不要删除或分享私钥。更换身份、清空浏览器数据或丢失私钥后，不能恢复旧身份的密文解密权限。不同中转站 URL 的浏览器存储彼此独立。

大厅历史永久保留，新加入的设备可以查看全部历史，密文仍受接收名单限制。中转站为每台设备保存已拉取的最新消息 ID；进入大厅默认加载最新 50 条，并保留本次旧游标供「跳转上次未读」按需定位。上线进入大厅时，未读密文会汇总在每页 20 条的弹窗中，也可随时打开「密文消息」查看历史；弹窗翻页不更新阅读游标。

本机中转站管理员可以通过「清理大厅历史」组合时间、发送设备、消息模式和跨页勾选消息（最多 500 条）。条件按交集（AND）生效，先预览数量再确认永久清理，预览后新消息不会被删除。未勾选单条时按筛选范围批量清理。清理不影响收发文件记录、设备连接历史和磁盘文件。

### 桌面重连凭证

桌面端将连接过的中转站凭证保存到本机 SQLite 的 `client_sessions` 表，应用重启后可在连接弹窗中选择原中转站，不依赖每次启动的控制服务端口。更换设备身份时清空这些凭证。手机仍使用对应站点的浏览器本地存储。

「本机加入」通过受保护的本机管理接口恢复本机身份，断开或重启后可再次加入；旧版遗失本机凭证时也无需重置身份，设备记录、文件历史和聊天密钥保留。远端桌面已有凭证在升级后仍遗失的，需在原中转站清除对应设备记录后重新配对。

重连优先使用原凭证，不消耗新的数字配对码；原凭证已失效且用户提供当前配对码时尝试重新配对。已登记的身份仍要求原凭证，不能仅凭设备 ID 和新配对码抢占已有设备。

### 设备头像

设备作为用户展示接入名称，群聊消息、连接设备、密文接收名单、本机身份与侧栏共用 avatarka 4.0.0 生成的头像。头像以设备 ID 为固定种子，使用统一命名空间、人物主题与配色；同一设备跨端、刷新、重连和改名保持一致，更换身份后生成新头像。设置页上方集中展示设备身份，可复制设备标识符。连接设备页显示累计登录次数，时间线为本机连接加上标记。SVG 仅在组件内存中动态生成并直接展示，不生成图片文件，也不写入数据库或浏览器存储。库随前端资源编译，运行时无需网络请求。

### 中转站名称与历史探测

设置页可独立修改中转站名称，与端口一起保存在本机 SQLite 中。旧版升级默认沿用原设备名称，之后设备名称和站名互不影响。中转站页的地址选项、群聊信息和连接历史一起展示站名。

打开连接弹窗会请求历史站点的 `/api/info`，不携带连接凭证、不自动加入，单个请求最多等待 3.5 秒，同期最多 4 个请求，可手动刷新。成功显示当前站名和在线设备数；未响应不能区分中转站关闭、网络隔离或地址变化。旧版缺少在线数时说明数据不可用，同地址的中转站身份变化时要求重新配对。

桌面侧栏以本机头像和名称开头，底部“关于”打开系统标准面板，GitHub 图标用默认浏览器打开项目主页。
